# 成功登录与终端连接通知

在后台「告警」选择 **SSH 成功登录、面板成功登录或终端成功连接**，再选择已有通知渠道。三个事件没有阈值参数，沿用渠道模板、语言和时区。

- `panelLogin` 是站点事件，范围固定为 `{mode: "site", serverIds: []}`，不关联虚构节点。
- `sshLogin` 和 `terminalConnected` 使用原来的全部／指定节点范围。
- 面板登录成功指凭据和 Turnstile 验证通过且 JWT 生成成功。
- 终端连接成功指已鉴权的 Agent 发送 `ready`，Broker 校验当前会话、连接、浏览器及凭据代次，并持久化 `running`。此前的 `terminal_audit.start` 不代表此成功事件。
- SSH 成功指 OpenSSH 写出 `Accepted … for … from …` 认证成功记录；不要求随后打开交互式 shell。失败尝试、登出和本系统 PTY 输出不属于 SSH 登录事件。

## SSH 需要 v1.4.0 / schema 10 Agent

`ssh_login_enabled=0|1` 和私有上报 `ssh_events.version=1` 使用 **schema 10**，采集器已随 [v1.4.0](https://github.com/emailtq/cfsm-agent/releases/tag/v1.4.0) 发布。先升级配套 Worker，再升级 Agent；v1.3.0/schema 9 不包含采集器。已启用自动更新的节点按既有周期升级，其余节点从后台安装／更新入口升级；发布不主动重装节点。

Worker 仍按原格式下发 schema 3–9 配置；没有 SSH 告警的节点不需要开启采集。面板／终端事件不依赖新的 SSH 采集器。新 Agent 继续接受原有 schema 7–9 配置及原配置入口。

启用状态由适用且启用的 SSH 告警规则及其启用渠道决定。网络配置只有布尔开关，不接受文件路径或命令。

### Linux OpenSSH：固定 journal 与文件来源

首次启用优先尝试已有 `journalctl`，只筛选 `sshd`、`sshd-session`、`sshd-auth` 标识符；没有可读 journal 时尝试 `/var/log/auth.log`、`/var/log/secure`。观察点建立后固定使用该来源，避免同时读两个日志出口而重复通知。

采集器以 Agent 运行用户的实际权限读取；不安装工具、自动提权、修改组、SSH 配置、服务或日志轮换配置。文件必须是可信所有者的常规文件，不接受可被其他用户写入的文件或符号链接。Windows、macOS、FreeBSD 等平台报告 `unsupported`；Dropbear 或其它日志格式不在此 OpenSSH 采集范围内。

首次观察从当前文件 EOF／journal 末尾开始，不回放既有登录。文件游标持久化，支持普通重命名到 `.1` 的轮换、可观察到的截断与截断后重新增长；只保存尾部同步摘要，不保存原始日志。journal 使用持久化 cursor，游标回收时记录 `rotation_gap` 并重新建立末尾观察点。

日志在读取前已删除／压缩，或截断后重建了不可区分的相同内容时，不能还原丢失记录。`rotation_gap` 会保留为诊断状态；请让日志保留时间覆盖预期积压。来源不可用、权限不足、私有状态失败和队列已满也有独立状态，管理员可通过私有 `get_login_event_status` API 获取。告警页只显示规则及投递结果未知提示，不再显示独立的 SSH 采集状态区域。`watching` 表示受控来源可读，不代表测试过该机器的 SSH 服务。

### 持久队列与确认

Agent 在实际配置文件旁的 owner-only `ssh-events.json` 中保存游标、节点／站点／Token 身份和最多 1024 个事件。每次最多报告 32 个；队列满时暂停读取，未确认事件不因断网、重启或普通报表成功而丢弃。关闭采集停止新读取，已排队事件仍等待明确确认。身份变化不把旧凭据的事件移交给新节点／站点。

[v1.4.1](https://github.com/emailtq/cfsm-agent/releases/tag/v1.4.1) 已发布及时上报调度，节点升级后生效，schema 10 不变。采集仍每秒检查一次；新事件持久入队后唤醒既有 HTTP／WSS 上报循环，不等 30–180 秒的指标周期。成功通道上的新批次及确认后剩余积压按一秒下限节流上报，没有事件时不增加报告。失败 POST 仍等待原报告间隔，协议暂停和报告熔断继续生效；等待确认的同一批次只随正常报告重试。实际延迟还包含日志可见性、私有状态写盘、指标采集和网络耗时。

Worker 经节点 Bearer 鉴权后，原子写入私有事件、渠道投递记录及流高水位，再返回：

- HTTP：`X-CFSM-Ssh-Ack: {"stream":"…","sequence":…}`，包括配置未变的 204 响应。
- WSS：正常上报 `ack` 中的 `ssh_ack`；独立于历史节流的 `persisted` 字段。

Agent 只释放已提供给 Worker 且流匹配的确认前缀。普通 2xx、实时提示 ACK、重复报告或重复确认不产生第二次通知。状态改变、现有配置心跳及排队事件才携带 SSH 元数据，不给每个空闲 2 秒指标报告添加 D1 状态写入。

时间为 Unix 毫秒。journal 的微秒时间转换为毫秒；传统 syslog 按节点本地时区推断年份，跨年时回拨。已有 Date 校准可用时修正报告时间；尚未校准时保留节点日志时间。用户名支持最多 64 个字符，排除 ASCII 控制字符、ASCII 空白与 DEL，包括国际化及域帐号；地址支持 IPv4、IPv6 与作用域标识。

## 通知与运行路径隔离

面板成功事件先落入既有全局 MetricsBroadcaster 的私有 KV，再后台转交 D1；D1 故障时由现有每分钟 cron 重试。无 DO 绑定的原调用入口继续使用 D1。终端 `running` 与独立成功事件 KV 在同一批 DO 存储操作中持久化；D1 不可用时保留成功事件，由现有 alarm 恢复。积压不塞进会话元数据数组，也不阻塞远端二进制数据或消费 ACK。

面板／终端在成功时固定适用规则身份、渠道 ID 和配置代次，随私有 KV 一起保存；D1 恢复后不会追溯采用后来启用的规则。SSH 在 Worker 耐久接受报告时固定目标。投递前再次检查当前规则、渠道、节点和凭据代次。禁用、删除及范围改变会在配置 CAS 的同一事务中取消不再适用的 D1 pending 投递，并保存最小规则／渠道失效代次；立即重新启用或恢复原范围也不能复活旧 KV 积压。无关规则改动不会取消仍有效的目标。节点删除或凭据失效也取消尚未发送的投递。已开始的渠道请求可能完成，无法撤回已经交给外部渠道的消息。

终端成功时的策略读取在 metadata mutation 外。该会话紧随 `ready` 的 Agent 字节按原信用上限暂候，随后按最新 attachment 累计转发，浏览器先收到耐久 `running` 的 `ready`；其它运行会话的二进制与 ACK 不等待该策略读取。如果成功时连通知策略都无法读取，面板／终端仍继续成功，并保存没有渠道目标的成功回执、记录 `success policy unavailable`；恢复后不猜测当时应发送给谁。

新成功事件每个渠道只尝试一次，复用已有发送器；HTTP 渠道请求有 8 秒超时，SMTP 不再额外重试。发送报错或中断后保留 `uncertain`，不自动重发，以免渠道已收到消息但响应丢失造成重复。该状态和数量在告警页可见，正常后续事件仍可投递。原资源、离线、流量、到期通知的重试行为不变。

完成、取消和未确认的投递记录保留七天。SSH 完成事件的详情随之清理，流高水位保留去重能力；面板／终端只保留最小身份回执。规则／渠道失效代次不含登录详情，保留以保护可能长期积压的 KV。pending 不因时间到期静默删除。

## 隐私与终端文本

报告只传递序号、时间、用户名、来源地址和认证方式；不传原始日志、密钥指纹、密码、JWT、认证请求或任意日志路径。SSH 元数据不进入 `metrics`、`samples`、历史曲线或公开 WSS；没有适用渠道时不保留登录详情。诊断 API `get_login_event_status` 仅向管理员返回来源状态和投递计数，原通知配置 DTO 不变。

终端把 `等待被控端连接 waiting for agent...` 写入普通 xterm 文本流并留在滚动历史。它不是远端输入，也不计远端二进制 ACK。重连保留正常缓冲区历史，等待旧字节解析完再重置旧应用模式；迟到的旧渲染回调不能污染新会话计数。欢迎文字和提示符只能来自远端输出，前端不生成 `Welcome to Alpine!` 或 `/opt/komari #`。
